# Telegram Service Bot

Telegram-бот для приёма заявок на услуги, записи на массаж и ЛФК, а также выдачи информационных материалов после проверки подписки на канал.

Проект следует общим правилам платформы ботов: редактируемый контент хранится в Directus, рабочие состояния — в PostgreSQL, приложение собирается в неизменяемый Docker-образ.

> Проект пока предназначен для локальной проверки. На Raspberry Pi он не развёрнут.

## Возможности

- три сценария заявки: массаж, ЛФК и помощь с выбором;
- согласие на обработку персональных данных до сохранения заявки;
- восстановление незавершённой анкеты после перезапуска;
- очередь доставки заявок в закрытую Telegram-группу;
- повторные попытки при временной ошибке Telegram;
- защита заявки от повторного создания по одному update;
- проверка подписки перед выдачей материалов;
- метки источника из ссылок `/start`;
- тексты, кнопки и комплексы из общей Directus CMS;
- однократная потоковая подготовка медиа из Яндекс Диска в Telegram с удалением технического сообщения;
- локальный контент по умолчанию при отключённой CMS;
- healthcheck, структурированные логи и корректная остановка контейнера.

## Архитектура

```text
Telegram
   │ long polling
   ▼
Telegram adapter ──► сценарии заявок
   │                       │
   │                       ▼
   │                  PostgreSQL
   │              сессии · очередь · статусы
   │
   ├──► Directus ── тексты · кнопки · материалы
   │
   └──► закрытая группа заявок
```

Directus не хранит активные анкеты и персональные данные. PostgreSQL не используется как редактор контента.

## Структура

```text
src/
├── config/        переменные окружения и логирование
├── domain/        типы и клавиатуры
├── health/        endpoint состояния
├── repositories/ PostgreSQL и контракты хранения
├── services/      CMS, media worker и доставка заявок
└── telegram/      Telegram API, polling и сценарии

deploy/            пример production-окружения без секретов

```

## Быстрый локальный запуск

Требуются Node.js 22+, npm и Docker Desktop.

```bash
cp .env.example .env
npm ci
docker compose up -d database
npm run dev
```

Перед запуском заполните в `.env` как минимум:

- `TELEGRAM_BOT_TOKEN` — токен от `@BotFather`;
- `TELEGRAM_ADMIN_CHAT_ID` — ID закрытой группы заявок;
- `TELEGRAM_CHANNEL_USERNAME` и `TELEGRAM_CHANNEL_URL`;
- `PRIVACY_POLICY_URL` и контакты оператора.

Для первой локальной проверки оставьте `DIRECTUS_ENABLED=false`. После проверки основных сценариев подключите общую CMS по [инструкции редактора](docs/CMS_CONTENT.md).

Полный чек-лист находится в [docs/LOCAL_TESTING.md](docs/LOCAL_TESTING.md).

## Работа с данными

- незавершённые анкеты удаляются через `SESSION_TTL_HOURS`;
- успешно доставленные и окончательно ошибочные заявки удаляются через `APPLICATION_RETENTION_DAYS`;
- ожидающие доставки заявки автоматически не удаляются;
- секреты хранятся только в `.env` или серверном env-файле;
- токен Telegram скрывается из структурированных логов.

## Релизы

Репозиторий подготовлен к Conventional Commits и SemVer. GitHub workflows проверяют код, собирают `linux/amd64` и `linux/arm64` образы и предусматривают выкладку точной версии.

Production workflow пока не следует запускать: серверный пользователь БД, env-файл и runner label для этого бота ещё не подготовлены.
