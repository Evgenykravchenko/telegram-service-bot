# Локальная проверка

Эта инструкция проверяет новый проект, не затрагивая Raspberry Pi и другие запущенные сервисы.

## 1. Подготовьте тестового бота

1. Откройте `@BotFather` в Telegram.
2. Создайте отдельного тестового бота командой `/newbot`.
3. Скопируйте токен в `TELEGRAM_BOT_TOKEN` файла `.env`.
4. Не используйте production-токен одновременно в старом и новом процессе: Telegram long polling допускает только одного активного получателя updates.

## 2. Подключите группу заявок

1. Создайте закрытую тестовую группу.
2. Добавьте туда бота.
3. Запустите приложение и отправьте в группе `/id`.
4. Скопируйте показанное число вместе со знаком минус в `TELEGRAM_ADMIN_CHAT_ID`.
5. Перезапустите приложение.

## 3. Подключите тестовый канал

1. Добавьте бота администратором канала.
2. Укажите username канала с `@` в `TELEGRAM_CHANNEL_USERNAME`.
3. Укажите публичную или пригласительную ссылку в `TELEGRAM_CHANNEL_URL`.

Приложение намеренно не запустится, если бот не является администратором указанного канала или не видит группу заявок.

## 4. Запустите локально

```bash
cp .env.example .env
docker compose up -d database
npm ci
npm run dev
```

На первом этапе оставьте:

```dotenv
DIRECTUS_ENABLED=false
```

Так можно проверить формы без зависимости от CMS. Комплексы будут отвечать, что материал ещё не опубликован — это ожидаемо.

## 5. Проверьте пользовательские сценарии

### Главное меню

- `/start` открывает меню;
- `/menu` сбрасывает текущую анкету;
- `/privacy` показывает ссылку на Политику;
- `/delete_data` показывает контакты оператора.

### Массаж

1. Выберите «Массаж».
2. Выберите вид массажа.
3. Заполните запрос, имя, телефон, время и дни.
4. Не принимайте согласие — заявка не должна появиться в группе.
5. Повторите сценарий и примите согласие — заявка должна появиться один раз.

### ЛФК и консультация

Пройдите обе анкеты и проверьте, что карточки имеют разные заголовки и поля.

### Перезапуск

1. Остановите приложение посередине анкеты.
2. Запустите его снова.
3. Отправьте следующий ответ.
4. Бот должен продолжить сохранённый шаг.

### Источник

Откройте ссылку вида:

```text
https://t.me/USERNAME?start=instagram_reels_15
```

В итоговой карточке должен появиться источник `instagram_reels_15`.

### Подписка

- без подписки бот предлагает подписаться;
- после подписки кнопка проверки выдаёт комплекс;
- если бот перестал быть администратором канала, ошибка видна в логах.

## 6. Подключите CMS

После базовой проверки создайте контент по [CMS_CONTENT.md](CMS_CONTENT.md) и включите:

```dotenv
DIRECTUS_ENABLED=true
DIRECTUS_URL=http://localhost:8055
DIRECTUS_TOKEN=...
```

Токен должен читать контент своего пространства. Для media worker ему дополнительно нужны чтение и изменение `media_assets` этого же бота.

Для проверки media worker добавьте:

```dotenv
YANDEX_DISK_TOKEN=...
TELEGRAM_MEDIA_CHAT_ID=-1000000000000
```

Создайте отдельную закрытую тестовую группу, добавьте туда бота и используйте её ID как `TELEGRAM_MEDIA_CHAT_ID`. Затем создайте небольшой Media Asset с путём на Яндекс Диске и статусом **В очереди**. Ожидаемый переход: `queued → processing → ready`.

## 7. Очистка локальной среды

Остановить контейнеры без удаления данных:

```bash
docker compose stop
```

Удаление локальной тестовой БД выполняйте только если она больше не нужна:

```bash
docker compose down -v
```

Эту команду нельзя выполнять на production-сервере.
